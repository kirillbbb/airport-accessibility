# Ограничения в аэропортах Москвы

Статический дашборд истории ограничений в Шереметьево (SVO), Внуково (VKO), Домодедово (DME) и Жуковском (ZIA).

**Период данных:** 23 сентября 2026, 00:00 — 23 октября 2026, 00:51 МСК. Последний день неполный. Данные собраны разово и автоматически не обновляются.

## Разделы сайта

- **Общий календарь** — главная страница. Все даты и четыре аэропорта на одном экране; цветные интервалы показывают время и тип ограничения. Нажатие на интервал открывает эпизод и источники, на дату — подробности дня.
- **Обзор** — количество эпизодов, длительность, сравнение аэропортов и распределение по дням и часам. Журнал объявлений доступен в раскрывающемся блоке.
- **О данных** — источники, правила расчёта, результаты сверки с другими сайтами и скачивание файлов.

Календарь и обзор используют общие фильтры дат, аэропортов и режима. Фильтры сохраняются в URL; текущую выборку можно скачать в CSV. На телефоне календарь прокручивается по горизонтали.

## Деплой

[Пошаговая инструкция для Vercel и GitHub Pages](docs/DEPLOY.md).

Проект готов к размещению: корень репозитория `./`, Framework Preset **Other**, Output Directory **dist**, команды сборки и установки пустые. Эти параметры заданы в [vercel.json](vercel.json). Переменные окружения не нужны.

Для GitHub Pages добавлен [workflow](.github/workflows/pages.yml), публикующий `dist/`. В **Settings → Pages → Source** выберите **GitHub Actions**, затем запустите **Actions → Deploy GitHub Pages**. Vercel и Pages могут работать одновременно из одной ветки `main`.

## Локальный запуск

Достаточно Python 3:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

Откройте [localhost:4173](http://127.0.0.1:4173/). Для загрузки ES-модулей и JSON нужен HTTP-сервер; открытие HTML как файла не подходит.

## Устройство проекта

```text
dist/                 Готовый сайт: HTML, CSS, JavaScript
  data/               Данные JSON/CSV, отчёты и архив исходных снимков
scripts/              Разовый сбор, нормализация и сверка
tests/                Проверки данных, расчётов и маршрутов
docs/                 Методология, результаты сверки и инструкция по деплою
vercel.json           Настройки статического хостинга
```

Фронтенд написан без фреймворка и сторонних JavaScript-библиотек. Браузер читает готовые файлы из `dist/data/`. Сервер приложения, база данных, API-ключи и установка npm-пакетов не требуются. Сборщики запускаются локально; Vercel обслуживает содержимое `dist/`.

## Источники и ограничения данных

Основной источник — [публичный канал Росавиации](https://t.me/s/favt_info). Дополнительные сообщения аэропортов и снимки агрегаторов сохранены для сверки. Исходные материалы и контрольные суммы находятся в `dist/data/evidence.zip` и `dist/data/collection-manifest.json`.

В наборе 98 эпизодов и 130 участков режимов. Длительность считается **между публикациями**, поэтому не является точным операционным временем. Режимы «приём и выпуск ограничены» и «по согласованию» учитываются отдельно.

Сумма длительностей по четырём аэропортам — 353 ч 27 мин. Она включает одновременные ограничения разных аэропортов. Пустой участок календаря не доказывает отсутствие ограничений. Три сводки без установленных границ сохранены отдельно и не добавляют часы к графикам.

Полного месячного архива SMS РСЧС и истории отдельных рейсов в наборе нет. Региональная опасность не приравнивается к закрытию аэропорта; причина БПЛА не присваивается автоматически. История не позволяет вычислить вероятность будущей задержки.

Подробности: [методология](docs/RESEARCH.md), [сверка с агрегаторами](docs/COMPARISON.md), [РСЧС и региональные оповещения](docs/RSCHS-AUDIT.md), [проверки исходного исследования](docs/VERIFICATION.md).

## Проверки и воспроизведение

Для проверок нужны Python 3.9+ и Node.js 20+. Зависимости устанавливать не требуется.

```sh
python3 scripts/prepare_research.py
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.mjs
node --check dist/app.mjs
```

Чтобы повторить обработку сохранённого среза без сети:

```sh
python3 scripts/prepare_research.py
python3 scripts/normalize.py
python3 scripts/compare.py
```

Первая команда распаковывает исходные снимки в `research/`. Этот каталог исключён из Git, поскольку те же файлы уже находятся в ZIP. Скрипты `collect.py` и `collect_airports.py` собирают открытые страницы и используют сохранённые копии при их наличии. Даты исследования фиксированы в скриптах; для нового периода нужно подготовить и проверить новый набор.
